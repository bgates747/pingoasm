# Regular-LOD full-owner transition recipe ABI

Status: **host generator, eZ80 consumer, exhaustive reference proof, and live
four-crossing emulator qualification implemented**.

The radius-five regular-LOD provider cannot safely transition its 91 detailed
objects separately from its coarse hierarchy. Every adjacent move introduces
11 detailed cells whose stable hash slots still contain different active old
cells. The static recipe table therefore treats all near and coarse owners as
one 255-slot staging domain and switches exact L0-coverage components.

## Recipe selection

There are 192 recipes, indexed by:

```text
((origin_q & 7) * 4 + (origin_offset_row & 3)) * 6 + direction
```

Direction is the executable order of `hex_provider_origin_steps`, not a
library neighbor order:

| Direction | Name | `dq` | `dr` |
| ---: | --- | ---: | ---: |
| 0 | north | 0 | 1 |
| 1 | south | 0 | -1 |
| 2 | northeast | 1 | 0 |
| 3 | southeast | 1 | -1 |
| 4 | northwest | -1 | 1 |
| 5 | southwest | -1 | 0 |

## Owner ordinals and regional edges

An ordinal names an entry in the **unbounded source plan**. It never names a
dense, clipped runtime plan:

- ordinals `0..90` are the radius-five near cells in `disk_offsets(5)` order;
- subsequent ordinals are `91 + static coarse phase-record index`.

Firmware must retain a source-ordinal-to-actual-slot map for both endpoint
plans. An invalid regional-edge owner maps to `0xff` and is skipped. It must
not be removed and cause later records to be renumbered. The interior-generated
coverage component is consequently a conservative supergroup at corpus edges:
missing members disappear, but a recipe can never select a different owner.

Detailed owners may finish a handoff in any manager slot. The historical
near-slot hash is a cold-plan convention, not a staging or final-residency
constraint. Live state therefore needs a unified tagged owner-to-slot map.

## Binary schema

The table begins with 192 three-byte pointers. The generated assembly include
uses native absolute `dl` pointers. The canonical host encoding uses u24
offsets relative to the start of the table so its bytes have an
address-independent hash.

Each pointer targets one variable-length recipe:

```text
group_count:u8
repeat group_count times:
    retiring_count:u8
    entering_count:u8
    old_source_ordinals[retiring_count]:u8
    new_source_ordinals[entering_count]:u8
```

Shared owners are absent from every group and remain active. For each group,
all entering owners are loaded and positioned into inactive slots while all
retiring owners remain visible. At a render-idle boundary the whole retiring
list is deactivated, the whole staged list is activated and published, and
only then may the released slots be reused. A load failure discards only that
group's staged work and leaves old coverage active.

`regular-lod-runtime.inc` intentionally remains the byte-identical historical

table; `scripts/build_regular_lod_group_scratch.py --group-staging 0` preserves

The exhaustive host test decodes every recipe, reconstructs every group from
old/new source ordinals, stages it under the 255-slot bound, and proves the
final active set is exactly the new endpoint. It covers all 32 phases times
six directions. Separate boundary samples prove that source-ordinal filtering
reconstructs clipped endpoint plans without renumbering.

The durable corpus audit decodes the generated bytes and enumerates all 50,183
valid origins and all 299,306 valid directed adjacent transitions. For every
step it reproduces the provider's dynamic choice: among groups that fit, prefer
maximum `retiring-entering`, then fewer entering owners, more retiring owners,
and finally earlier encoded source order. Edge filtering caused 347,569 groups
to be chosen ahead of the next encoded group. The audit applied 6,146,608
nonempty clipped groups, found endpoint occupancy `61..250`, preserved the
14-owner per-side and 15-owner total maxima, retained the minimum four-slot
staging margin, encountered no dead end, and reached the exact clipped target
every time. The recorded run completed in 23.135 seconds.

The promoted eZ80 consumer preserves an authoritative unified owner-to-slot map,
stages at most one entering mesh per idle pass, and commits each selected group
without a render interleave. A live debugger trace crossed four north cell
boundaries from Berkeley Marina, reached the exact host-predicted endpoint after
every transition, and observed no command-50 replacement of an active slot and
no coverage hole. A second gate selected radius four after the unified endpoint:
all 227 old objects deactivated before the first refill publication, the camera
and origin `(80,129)` were preserved, and the exact 196-owner cold endpoint
converged with zero staged objects or errors. Radii zero through four are
stationary review modes; adjacent regional recipes remain radius-five only.
