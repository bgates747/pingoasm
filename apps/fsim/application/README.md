# Regular-LOD C/assembly application

This is the sole active FSIM application. It combines an AgonDev C policy
module with the proven eZ80 assembly runtime. Fixed-point mathematics, terrain
loading, transforms, MOS/VDP communication, staging, and atomic publication
remain assembly. C owns only bounded coverage-group selection. `C_GUARDED` is
authoritative and permanently falls back to the accepted assembly selector if
the module or a returned candidate fails validation.

The tracked tree contains all source, compact contracts, builders, manifests,
and focused tests needed to reproduce the application. Acquired GeoTIFFs and
generated terrain corpora live under ignored `data/downloads/` and `build/`;
they are checksum-qualified inputs and outputs, not repository payloads.

## Build

From this directory:

```bash
make client
```

That rebuilds the accepted assembly control, the fixed-address C module, and
the canonical guarded-C program using the existing generated hierarchy.

To regenerate the terrain inputs and application from the pinned manifest:

```bash
make soup-to-nuts
```

This requires the third-party files named and hashed by
`data/manifests/bay-area-2026-08-02.json` to be present under the ignored
`data/downloads/` tree. No download occurs during an ordinary build.

The runtime products are written under
`build/p3dm/bay-area-regular-n1-hierarchy/`:

- `P3DRGLC.BIN` — canonical combined client;
- `CPOLICY.BIN` — fixed-address AgonDev policy module;
- `MANAGERC.json` — runtime binding receipt;
- terrain containers and material resources generated by the corpus build.

Run the focused static and build regressions with:

```bash
make test
```

The exact `C_GUARDED` image was interactively exercised and accepted in the
emulator on 2026-08-15. Physical-hardware execution remains the outstanding
human gate. Optimization is intentionally deferred until application behavior
is complete.

## Layout

- `experiments/agondev-regular-policy/` — C ABI, linker, source, provenance;
- `fixtures/` — assembly application and its minimal include closure;
- `runtime/ez80/` — universal transactional terrain manager;
- `src/pingo_terrain/` — deterministic terrain/corpus generators;
- `scripts/` — build and correctness qualification commands;
- `tests/` — focused active-application regressions;
- `data/manifests/` — pinned third-party input identities;
- `build/`, `data/downloads/`, `.venv/`, `emulator/` — ignored local state.
