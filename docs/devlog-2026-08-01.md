## PingoWolf emulator consolidation and recovery

The emulator failure was configuration drift rather than a new rendering
regression. Two PingoASM emulator trees had accumulated incompatible runtime
identities: the singular profile still linked a Pingo-only userspace module,
while `emulators/tv-port-baseline` retained a copied historical module. One
launch also lacked the matching `mos_console8.map`, so Fab disabled its
directory-backed SD card and MOS reported an SD-card failure. Launching from a
directory containing stock firmware further made an explicit bespoke-module
failure capable of degrading into a misleading stock-VDP run.

The Author rejected maintaining parallel modern firmware lines. The durable
rule is now one living combined branch and one mutable project emulator:

1. `~/Agon/mystuff/agon-vdp`, branch `pingowolf`, owns both Pingo and Wolf;
2. `~/Agon/mystuff/pingoasm/emulator` is PingoASM's only project-local
   emulator profile; and
3. older renderer states are preserved by Git tags or release artifacts, not
   additional development profiles.

Both former emulator trees were removed, and the canonical
`agon-dev-env/scripts/setup_emulator.py pingoasm` path recreated the singular
profile. It now links the owned Fab executable, matching Console8 MOS binary
and map, and `pingowolf`'s `vdp_combined.so`. Its emulated SD card maps the
canonical `apps`, `tests/apps`, and `benchmarks` trees directly. A
`.bespoke-vdp-profile` marker forces the launcher down the bespoke path even
when the module is missing; the launcher resolves every input before startup,
runs from a temporary directory without stock firmware fallback, and exits
without falling through into the ordinary emulator launcher. Missing-module
and clean-exit tests passed.

The deprecated TurboVega fixture directory and active build dependencies were
retired. Generated benchmarks now consume the neutral
`benchmarks/_common/vdu_pingo.inc` helper and the authoritative Cube and
HeavyTank models under `src/asm/models`. All 32 render-spin fixtures, three
orbit-scene fixtures, and the asynchronous fixture regenerated and assembled;
zero generated `vdu_tv.inc` files remain. The 18-sample build and all 148
Python regressions passed.

The combined userspace module rebuilt from `pingowolf` commit `3c07e75`; the
complete Pingo, Wolf, bridge-robustness, lifecycle, and cross-subsystem native
suite passed. The Author then visually accepted both maintained applications

## Interactive Earth-relative camera controls

Both maintained Earth Party editions gained the same application-owned camera
controls without changing Pingo firmware semantics. Page Up/Page Down move the
camera along world Y; Home/End move it toward or away from Earth's center;
Insert/Delete sweep it around world Y while preserving its radius and
elevation. Earth is only the position reference. Every resulting camera pose
continues to aim at the user-controlled Jet, and only absolute camera state is
sent to the write-only VDP.

The camera retains cylindrical state and regenerates Cartesian position from
bounded radius, world Y, and sweep values. This avoids accumulated sweep drift
and cancels opposed controls before rounded updates. Its initial radius is now
5,450 world units: the original 4,200-unit Earth distance plus half the
2,500-unit party orbit radius.

Initial emulator testing showed correct Jet tracking but apparently inert
camera keys. A broad source search found the Author's hand-written MIDI organ
under `agon-utils/examples/midi/organ`. Its existing binary continuously dumps
the complete MOS keyboard bitmap and proved all six extended keys reached MOS
at the documented offsets. A forced-sweep diagnostic then failed while a
direct indexed camera-state translation succeeded, isolating the fault after
input and before submission.

The defect was misuse of eZ80 `LD.S` for absolute 16-bit scalar loads and
stores. The suffix changes execution/address mode; it is not merely an operand-
width annotation, and short-mode stack operations likewise do not share ADL's
24-bit stack. The final implementation transfers scalar bytes explicitly in
ordinary ADL mode. Temporary forced-motion diagnostics were removed. Human
emulator review then confirmed all camera controls and continuous Jet tracking.

The display background changed to palette index 16, Navy `(0,0,85)`. During
asset submission both editions show a concise Jet/camera control card. At the
end of loading they print a blank line and `Ready. Press any key to begin.`,
then use the local `waitKeypress` wrapper before switching to graphics mode.
The durable `apps/earth-party-controls.md` is the short user-facing reference.

The focused camera/build suite contains 24 tests, including shared-source,
key-map, coordinate-generation, aim-target, background, short-mode guard, and
startup-gate checks. Both maintained applications assemble successfully and
the flat edition passed interactive emulator review.

## Flat PingoWolf SD deployment

`build/scripts/deploy_pingowolf_sd.py` now owns the combined application-card
layout. It requires a mounted Agon card and validated nonempty sources, rejects
symlinked destinations, clears only the exact `/PingoWolf/Pingo` and
`/PingoWolf/Wolf` leaf directories, and repopulates each without subdirectories.
Pingo receives the complete current `earth-party-flat/tgt` payload. Wolf
receives its current executable plus level-0 tiles/sprites, HUD, and sound AGNB
containers from their authoritative Wolf3DOrig paths.

The script writes CRLF `autoexec.txt` containing only `SET KEYBOARD 1` and
`cd /PingoWolf`. The first deployment produced eight Pingo files and five Wolf
files; both application binaries compared byte-for-byte with their sources.
The card was flushed and safely unmounted after verification.
