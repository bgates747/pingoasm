## Drift-free sampled pose cycles — Ultra reasoning

The Earth-spin judder investigation first bypassed the fixed-basis routine and
ran Earth through the ordinary persistent-object integrator. That comparison
was decisive but negative: the compound tilted orientation accumulated large
axis error and periodically snapped to a correction. The earlier fixed-basis
path prevented that precession, but its final `p3d_mat3_to_euler16` conversion
still quantized through the 256-phase inverse-trig tables. A host oracle found:

1. maximum rendered-pose error of 1.242 degrees;
2. adjacent step sizes from 0 through 2.37684 degrees around the intended
   1.40625-degree step; and
3. four duplicate adjacent poses per revolution.

This was not repaired inside the ordinary free-motion pipeline. A sampled
closed cycle is an application policy, whereas the Jet and orbiters require
general interactive integration. Changing their core path would expand both
risk and scope without helping Earth.

Instead, `generate_pose_cycle.py` now provides a reusable offline generator
parameterized by base Euler pose, local X/Y/Z spin axis, and 2–256 samples. A
sample is a complete 24-byte orientation record:

1. six bytes of fine absolute Pingo wire Euler angles, using the documented
   32767 units per turn; and
2. an 18-byte row-major signed-Q15 matrix for eZ80 local-space calculations,
   whose fast-trig phase domain uses a 32768-unit binary turn.

Keeping both forms explicit avoids a subtle one-unit domain conflation,
removes runtime inverse trigonometry, and lets later sampled animations retain
correct local-axis movement. `apps/_common/pose-cycle.inc` supplies the generic
`p3d_object_apply_pose_sample8` loader. Each Earth Party builder copies that
helper into its portable `src/` and generates an app-local
`earth-spin-cycle.inc` from the profile's authoritative tilt values. Generated
files carry loud provenance banners.

Earth retains its `(0,128,0)` local angular velocity. The application wraps
the accumulated internal phase modulo 32768, selects the nearest of 256
samples, and applies the matching wire/matrix pair. The first dynamic pose is
sample 1; sample 255 advances to sample 0, closing byte-exactly after 256
ticks or 8.533 seconds at 30 Hz. The same implementation is present in both
`earth-party-local` and `earth-party-flat-local` so the rendering-policy
sibling does not silently acquire different simulation semantics.

The independent numerical regressions establish:

1. all 256 emitted poses are unique;
2. maximum wire-pose error is approximately 0.0107 degree;
3. adjacent rendered steps span 1.39697–1.41514 degrees;
4. phase/index state closes exactly without ever selecting record 256;
5. the initial Q15 matrix remains byte-identical to the accepted tilted basis;
6. the 1,536-byte Euler subset has SHA-256
   `d491ca1ec17035bc921c8de70aada5674cfc8a7bf104831c04c94d528453b7f3`;
   and
7. the complete 6,144-byte pose payload has SHA-256
   `f0ab80b0936c652fbec05fd071c5dfd9965e322b10d6a53f25e2be144c70a5d8`.

Both dedicated builders assemble successfully. The generated executables are
186,110 bytes for `earth-party-flat.bin` and 200,658 bytes for
`earth-party.bin`, safely inside the existing 512 KiB executable-plus-staging
guard. All 147 Python regressions pass, the complete 18-binary build succeeds,
and a second pair of builds reproduces all executable and generated-include
hashes byte for byte. A disposable emulator using the canonical app symlink
ran `earth-party-flat.bin` continuously without protocol or callback errors.
The Author watched the formerly troublesome rotation intervals and confirmed
that the sampled cycle fixed the visible correction snap. This qualifies the
implementation upgrade on the emulator. No persistent emulator snapshot was
modified; physical-hardware qualification can follow independently.

### Integration corrections and guardrails

The shared bridge now implements the following reviewed behavior:

1. Wolf controls use an independent explicit registry with targeted/global
   teardown. Unknown and truncated commands do not publish persistent state.
   Existing controls are held by a local `shared_ptr` across reentrant work.
2. Wolf's former global scratch buffer IDs `0xFFFC` through `0xFFFE` were
   replaced with local PSRAM streams and bitmap wrappers. Wolf rendering can no
   longer destroy valid Pingo or ordinary resources at those IDs.
3. Pingo's raw `BufferStream` control storage now uses placement construction
   and explicit destruction, with representation assumptions pinned by static
   assertions.
4. Generic callback dispatch iterates a stable ID snapshot. Pingo emits its
   completion packet only after every diagnostic/member access has finished,
   because a synchronous callback may destroy the active control.
5. Debug lookup remains read-only and cannot create a ghost ordinary buffer
   beside a Wolf-only control.
6. Wolf tile access rejects a live Pingo control at use time, then automatically
   recovers if that ID is later recreated as ordinary tilemap storage.
7. A first ordinary write over Pingo removes the dead in-place control block;
   subsequent ordinary writes retain the established multi-block append
   semantics. The regression checks exact block count, sizes, bytes, and a real
   Wolf tile read of the replacement.
8. Pingo creation is now transactional. Dimensions and private allocation/
   initialization are completed before the existing ordinary, Pingo, or Wolf
   occupant is cleared. Invalid dimensions and deterministic allocation
   failure preserve the prior occupant and its exact state; successful creation
   commits through canonical teardown. Writable-buffer creation likewise
   allocates before releasing a typed-only occupant.
9. A late Wolf compatibility subcommand `40` and `W3DV` response were rejected
   from this milestone after ownership review. The shared known-command
   allowlist is restored to Wolf subcommands 0 through 17 plus 41; any future
   version query must arrive as a coherent, stateless Wolf-owned nomination.
