# Pingoasm devlog — 2026-07-31

## Earth Party flat-vehicle and emissive-star sibling

`apps/earth-party-flat-local` is a new isolated rendering-policy fixture based
on the current `earth-party-local` (the Author's “earthpartyjet”). It began
without modifying the original application or its concurrently developed
real-star assets. The later sampled-pose correction described below is now
shared by both variants; their rendering policies remain distinct. The sibling
retains the same objects, simulation, controls, camera tracking, positions,
scales, velocities, 30 Hz fixed-step rules, 320x240 viewport, and asynchronous
render-completion discipline.

Only the requested render policy changes:

1. Jet and Airliner are converted to one predominant Agon palette color per
   source triangle and remain scene-lit.
2. All six star-sector meshes select their already constant per-triangle atlas
   colors, are flat shaded, and are self-illuminated.
3. Earth, Crash, Lara, and HeavyTank remain perspective textured and
   scene-lit.
4. Scene ambient is 32/127, the nearest encoded quarter-unity floor. The
   explicit light direction is `(-16384,0,28377)`: 30 degrees counterclockwise
   from `+Z` in the X-Z plane. Unity directional intensity is unchanged.

The existing `flat_palette.py` conversion selected 16 palette indices across
Jet's 736 triangles and nine indices across Airliner's 3,855 triangles. Both
generated includes pass final encoded-UV validation. Their separately named
runtime textures are byte-identical copies of canonical `colors64.rgba2`,
allowing the existing application loading sequence and bitmap IDs to remain
unchanged.

The dedicated `build_earth_party_flat_local.py` builder regenerates the six
model includes and real-star sky, validates both flat vehicle meshes, assembles
`earth-party-flat.bin`, enforces the established 512 KiB staging window, and
atomically promotes the payload. Two consecutive builds produced identical
hashes for the executable and all seven RGBA2222 assets. The fixture is also
part of the complete successful 18-binary `build_samples.py` run.

Mixed lit and emissive meshes required firmware subcommand 48, an independent
mesh illumination policy. Mode 0 inherits scene illumination and remains the
zero-initialized compatibility default; mode 1 emits native colors. Shading
mode and illumination policy remain orthogonal.

The first disposable emulator attempt accidentally used the preceding native
module and was rejected as evidence for self illumination. After an explicit
native rebuild, the corrected module hash was
`b1d40de914f059b6ccb6218d38cee1e9e5b91f34837afb671c3b09c673c28080`.
The corrected disposable run did not alter the persistent emulator snapshot.
The Author confirmed that Jet and Airliner rendered properly and retained
their shapes well despite simplification. The known emulator-only symptom in
which the bottom quarter of the viewport is absent also appeared; this remains
separate from the fixture and awaits hardware ground truth.

An adversarial review found no protocol, renderer, or simulation defect. It
did identify two build-provenance details worth preserving explicitly:

1. The sibling regenerates all model includes with the current canonical UV
   encoder. Consequently, the otherwise unchanged EarthUV and HeavyTank data
   contain small UV-word differences from the older, stale generated includes
   in `earth-party-local`. Reverting those values would reintroduce obsolete
   generator output, so the sibling retains the canonical regeneration; this
   is an asset-encoding delta, not a simulation or handwritten-code change.
2. Clean-checkout reproducibility requires the real-star generator/catalog and
   the current authoritative Crash/Lara model sources that are presently part
   of the uncommitted Earth Party work. Those dependencies must accompany or
   precede the fixture when commits are eventually prepared.

The builder now also verifies the canonical 8x8 palette image and the accepted
RGBA2222 SHA-256 before copying the palette for Jet and Airliner. This adds a
failure guard without changing the accepted executable or texture payloads.

The rendering-policy fixture subsequently passed matching emulator and
physical-hardware visual review. No pose-cycle work below has been committed
or pushed.

## Drift-free sampled pose cycles — Ultra reasoning

The Earth-spin judder investigation first bypassed the fixed-basis routine and
ran Earth through the ordinary persistent-object integrator. That comparison
was decisive but negative: the compound tilted orientation accumulated large
axis error and periodically snapped to a correction. The earlier fixed-basis
path prevented that precession, but its final `p3d_mat3_to_euler16` conversion
still quantized through the 256-phase inverse-trig tables. A host oracle found:

1. maximum rendered-pose error of 1.242 degrees;
2. adjacent step sizes from 0 through 2.37684 degrees around the intended
   1.40625-degree step; and
3. four duplicate adjacent poses per revolution.

This was not repaired inside the ordinary free-motion pipeline. A sampled
closed cycle is an application policy, whereas the Jet and orbiters require
general interactive integration. Changing their core path would expand both
risk and scope without helping Earth.

Instead, `generate_pose_cycle.py` now provides a reusable offline generator
parameterized by base Euler pose, local X/Y/Z spin axis, and 2–256 samples. A
sample is a complete 24-byte orientation record:

1. six bytes of fine absolute Pingo wire Euler angles, using the documented
   32767 units per turn; and
2. an 18-byte row-major signed-Q15 matrix for eZ80 local-space calculations,
   whose fast-trig phase domain uses a 32768-unit binary turn.

Keeping both forms explicit avoids a subtle one-unit domain conflation,
removes runtime inverse trigonometry, and lets later sampled animations retain
correct local-axis movement. `apps/_common/pose-cycle.inc` supplies the generic
`p3d_object_apply_pose_sample8` loader. Each Earth Party builder copies that
helper into its portable `src/` and generates an app-local
`earth-spin-cycle.inc` from the profile's authoritative tilt values. Generated
files carry loud provenance banners.

Earth retains its `(0,128,0)` local angular velocity. The application wraps
the accumulated internal phase modulo 32768, selects the nearest of 256
samples, and applies the matching wire/matrix pair. The first dynamic pose is
sample 1; sample 255 advances to sample 0, closing byte-exactly after 256
ticks or 8.533 seconds at 30 Hz. The same implementation is present in both
`earth-party-local` and `earth-party-flat-local` so the rendering-policy
sibling does not silently acquire different simulation semantics.

The independent numerical regressions establish:

1. all 256 emitted poses are unique;
2. maximum wire-pose error is approximately 0.0107 degree;
3. adjacent rendered steps span 1.39697–1.41514 degrees;
4. phase/index state closes exactly without ever selecting record 256;
5. the initial Q15 matrix remains byte-identical to the accepted tilted basis;
6. the 1,536-byte Euler subset has SHA-256
   `d491ca1ec17035bc921c8de70aada5674cfc8a7bf104831c04c94d528453b7f3`;
   and
7. the complete 6,144-byte pose payload has SHA-256
   `f0ab80b0936c652fbec05fd071c5dfd9965e322b10d6a53f25e2be144c70a5d8`.

Both dedicated builders assemble successfully. The generated executables are
186,110 bytes for `earth-party-flat.bin` and 200,658 bytes for
`earth-party.bin`, safely inside the existing 512 KiB executable-plus-staging
guard. All 147 Python regressions pass, the complete 18-binary build succeeds,
and a second pair of builds reproduces all executable and generated-include
hashes byte for byte. A disposable emulator using the canonical app symlink
ran `earth-party-flat.bin` continuously without protocol or callback errors.
The Author watched the formerly troublesome rotation intervals and confirmed
that the sampled cycle fixed the visible correction snap. This qualifies the
implementation upgrade on the emulator. No persistent emulator snapshot was
modified; physical-hardware qualification can follow independently.
