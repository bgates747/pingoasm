# Development log — 2026-07-30

## eZ80-owned local move-object client

`apps/moveobj-local` now provides a hand-developed Cube client for current
Pingo. It replaces the retired firmware-owned object-local delta commands with
the tagged AgonMaths integer 3D API.

The client owns a packed object state containing resource IDs, absolute world
position, canonical Pingo Euler rotation, scale, local-to-world orientation,
local linear/angular velocity, and angular residuals. Initial synchronization
uses absolute commands `5`, `9`, `13`, and `17`. Each changed input tick calls
`p3d_object_step16`, then synchronizes only dirty absolute rotation and
translation before rendering.

The historical interaction contract is retained:

1. a 12/120-second MOS countdown;
2. OR-latched keyboard samples during the wait;
3. W/S, A/D, Page Up/Page Down local translation;
4. Q/E, arrows local rotation;
5. rotation before translation; and
6. timer reset after no-op handling or rendering.

Space-to-cycle-dithering is disabled. Historical command `41` carried one
dithering byte, while current command `41` registers render completion with a
three-byte payload. Sending the old packet could desynchronize the VDU stream.

The client uses a current command-scoped VDU helper derived from
`apps/turbovega/src/vdu_tv.inc`. UV commands `3` and `4` correctly receive the
mesh ID. The managed object is created and updated only by the 3D state API;
there is no duplicate `CO`, `SO`, relative, or ad-hoc absolute object path.

## Asynchronous Jet evolution

The synchronous Cube client then passed interactive emulator and physical
hardware review. The next revision changes the visual test model to the Jet
and separates simulation cadence from rendering:

1. MOS's 120 Hz clock drives a fixed four-tick, 30 Hz simulation step.
2. Linear and angular rates are expressed per 128 MOS ticks.
3. Rates `352` and `4864` therefore become exact shift-derived per-step
   deltas `11` and `152`.
4. The eZ80 continues applying local transforms while one Pingo render is in
   flight.
5. A completed render is displayed and flipped before the newest dirty
   absolute pose is submitted for the next render.
6. Intermediate rendered poses are coalesced; authoritative world state is
   never discarded.

The client now opts into current command `41` using the exact packet:

```text
VDU 23,0,&A0,sid; &49,41,1,token;
```

Mode `0` plus a mandatory zero token disables notifications. The MOS keyboard
vector receives the ten-byte `P3DR` version-1 completion payload, copies it to
an application mailbox inside the UART interrupt path, and performs validation
and display work later in foreground code. Exactly one render may be in
flight. Notifications are disabled before the callback is removed on exit.
The old Space binding remains disabled because its obsolete one-byte command
`41` packet is incompatible with this contract.

The render target remains 320×240 through `viewport_width` and
`viewport_height`. Those constants are deliberately the primary renderer
performance knob: reducing resolution shortens render occupancy without
changing the 30 Hz simulation rate. There is no artificial render limiter;
hardware viewport tuning should seek roughly 12 FPS minimum and preferably
15 FPS.

The decoupling does not remove every source of input latency. Pingo rendering
currently blocks the VDP command loop, including transmission of keyboard
packets to MOS. Held input can continue driving fixed eZ80 updates, but a new
press or release may not be delivered until the outstanding render finishes.
Normal four-byte keyboard records are left untouched by the callback and MOS
updates its virtual-key map after the callback returns.

The static build now preserves `src`, copies `jet.rgba2`, and assembles
`src/jet.asm` to `tgt/jet.bin`. The previous synchronous Cube result remains a
qualified historical milestone; this asynchronous Jet revision requires a new
interactive emulator and hardware validation gate.

Machine verification of the Jet revision completed:

   `AgonMaths/3d/src/asm/agon` snapshot;

## Persistent-throttle moveair sibling

`apps/moveair-local` now applies the historical moveair control layer to the
same current-Pingo asynchronous renderer and eZ80-owned pose used by
`moveobj-local`. The two applications deliberately retain self-contained
source trees, while regression tests require their `render-async.inc` files to
remain byte-identical.

The fixed simulation step remains four MOS ticks at 30 Hz. Local-linear Z is
now persistent state rather than a fresh keyboard delta: W increases forward
throttle by making the velocity more negative, S decreases it toward zero,
and the historical magnitude limit is 255 with no reverse thrust. Any nonzero
throttle therefore invokes `p3d_object_step16` and dirties the object's world
position every simulation quantum even with no key held. Up/Down apply pitch,
Left/Right apply roll at twice the pitch rate, and A/D apply yaw. Angular
velocity is transient and is rebuilt every quantum.

The old firmware-owned camera-track-object operation, Pingo command `42`, is
not supported by current Pingo and is intentionally absent. The historical
instrument panel, panorama, second model, and their textures are also omitted:
this focused transform client renders only the Jet and packages only
`jet.rgba2`. Space/dithering remains disabled because command `41` belongs to
render-completion registration.

The static-app manifest now builds both local clients without rewriting their
sources, bringing the full build to 15 binaries. Common source guards run
against both apps, reject command `42` and retired local-transform helpers,
and specifically require persistent-Z integration in `moveair-local`.

Machine verification assembled all 15 binaries and passed all 90 Python
regressions. Interactive emulator and physical-hardware review remain the
qualification gates for the new persistent-throttle control layer.

## eZ80-owned tracking camera

The retired firmware-owned camera-track-object command was replaced with
eZ80-side camera state and absolute current-Pingo commands. The canonical
AgonMaths library now supplies a packed 36-byte camera state plus
`p3d_camera_aim_at_point16`, `p3d_camera_aim_at_object16`, and dirty
camera-command synchronization.

The solver uses precision-reduced integer Cartesian-to-polar operations and
fine interpolated trigonometry. Its contract requires an explicit roll policy:

1. `p3d_camera_roll_upright` retains a world-up horizon; and
2. `p3d_camera_roll_continuous` crosses a pole smoothly and may emerge
   inverted.

The upright implementation retains the last reliable yaw inside a hysteretic
pole cone, preventing gimbal-lock chatter when the target passes directly
above or below the camera. Deterministic host tests cover fly-bys at multiple
distances and speeds, the half-turn seam, scaled trajectories, render-rate
sampling, and pole entry/exit.

The first interactive moveair camera was broadly correct but visibly snapped
between coarse angle bins. Fine interpolation and retained pole state removed
that judder. A separate held-down-control freeze exposed a matrix-only
one-count overflow at a rounded Q15 cardinal. Matrix composition now clamps
only the exact `+/-32768` boundary to `+/-32767`; larger overflows still fail.
Long held-control regression vectors cross every cardinal in both directions
and prove the simulation step cannot stall there again.

The corrected tracking camera passed interactive emulator review and physical
hardware review. The hardware result was smooth, showed no obvious frame
judder, and no longer froze under the formerly failing pitch input.

## Interactive Earth Party stress scene

`apps/earth-party-local` combines the qualified moveair Jet and tracking camera
with Earth, Crash, Lara, HeavyTank, and Airliner. The eZ80 owns all six world
poses. Earth spins around a fixed tilted basis whose north pole points
screen-left and toward the camera. The four orbiters start 90 degrees apart
and receive only persistent local `-Z` linear velocity and local `+Y` angular
velocity.

No world-space orbit positions are scripted after initialization.
`p3d_object_step16` produces each circular path using the same local-motion
contract as the controlled Jet. All four orbiters close position, Euler
rotation, orientation matrix, and angular residual byte-for-byte after 128
fixed simulation ticks. Radius stays within `2500.0..2516.1`.

The profile-driven builder regenerates six symbol-prefixed model includes and
six RGBA2222 textures, assembles transactionally, preserves the previous
target after any failure, and rejects profile paths or names that could escape
the intended source/target boundaries. The complete project build now
produces 16 binaries, and the Python suite contains 96 passing tests.

Human review of the qualified copied-snapshot emulator found the scene
beautiful and continuously playable. An attempted Blender automation pass to
turn Crash and Lara was fully rolled back after the Blender 4 export changed
the Crash UV table representation. Independent comparison proved the face
vertex/normal streams and per-corner UV values remained valid, so this was not
the cause of the later blank screen.

## Emulator-profile qualification lesson

The apparent post-export regression was a profile-selection error. The
mutable development profile:

```text
emulator
```

accepted every mesh and object but produced one empty 1 ms frame for this
fixture. The visually qualified run—and the recovered continuous run—used:

```text
emulators/tv-port-baseline
```

Despite its historical directory name, that profile is the isolated copied
current-Pingo snapshot with the render-completion behavior required by these
clients. Its native VDP differs byte-for-byte from the mutable profile. The
recovered canonical build produced hundreds of continuous `P3DR` completions
there. Future visual qualification must record the exact profile and VDP hash,
not merely say “the Pingo emulator.”
